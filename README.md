# GameNet

GameNet exposes a local **TCP** game server through a public relay. The player connects to a TCP port on the relay; the relay forwards that traffic to the host agent over an encrypted QUIC connection. That QUIC connection requires TLS 1.3 with `X25519MLKEM768` hybrid post-quantum key exchange and has no conventional-key-exchange fallback. Server certificates still use conventional authentication, and the player-to-relay connection is not encrypted by GameNet.

Run `gamenet host minecraft` or `gamenet host --port 7777`. The relay chooses an available TCP port from `10000..=10999` and prints the address to share. It binds the port before announcing it. If the host disconnects, GameNet holds that port for five minutes and the running CLI retries automatically. After five minutes, the next registration may get a different port.

The host's ordinary identity is stored in `~/.config/gamenet/identity.bin`. A separate `recovery.bin` is created when hosting starts. GameNet restricts both files to the current user on Unix and Windows, including older files when it loads them. After the first successful host connection, run `gamenet show-recovery-code` and save the 64-character code in a password manager, separate from `identity.bin`. The command prints a secret; avoid sharing its output or saving it in a shell log.

If only `identity.bin` is stolen, stop your host and run `gamenet recover-identity`. The relay checks the recovery key, closes the old active tunnel if needed, transfers its unexpired port claim to a new identity, and rejects the old token for that claim. On another computer or after losing `recovery.bin`, the command privately prompts for the saved code. Use `--use-backup-code` to prompt even when a local recovery file exists. Then run `gamenet host` again. If recovery is interrupted, rerun the command: the private `identity.bin.pending` keeps the replacement token stable. Recovery works only while the port claim is active or in its five-minute reconnect window. If an attacker also gets the recovery key, or takes over before an older claim is first enrolled, this account-free relay cannot tell who the rightful owner is. Revoking a claim does not ban someone from creating a fresh anonymous tunnel with another token.

For routine replacement when no attacker is active, stop hosting, run `gamenet rotate-identity`, then host again. This transfers an unexpired claim, but cannot displace an active tunnel. A port claim can be rotated once before it expires; if it has expired, rotation creates a new identity without reserving the old port.

To keep one host from occupying the public relay, each IPv4 address or IPv6 `/64` network can hold at most two active or reconnect-window tunnel ports and four connections awaiting registration. The relay also caps pending registrations globally at 128 and gives each one ten seconds to finish. Waiting for friends does not disconnect a live host. These address-based limits cannot prevent abuse spread across different networks.

UDP games such as Minecraft Bedrock and Valheim are not supported yet. A UDP-only preset returns an error instead of creating a nonworking TCP tunnel.

The relay's QUIC listener uses UDP port `5000`. A production relay must set both `GAMENET_TLS_CERT` and `GAMENET_TLS_KEY` to readable certificate and key files; startup fails if either is missing or invalid. For local development only, set `GAMENET_DEV_SELF_SIGNED=1` to create a self-signed certificate and use the host CLI's `--insecure` flag. The relay loads certificates at startup, so renewing one currently requires a restart. The relay state file contains expiring token fingerprints rather than bearer tokens. On first startup with the older permanent-reservation file, GameNet creates an owner-only `gamenet-state.json.legacy-backup`; that backup still contains bearer tokens and should be removed after the migration is verified.
